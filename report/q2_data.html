4. What Can Data Fix?

Models B, C and D are trained under exactly the same protocol as model A (mm/train.py), with these changes. B: for each training window, g is drawn uniformly from the 8 elements of G (including the identity) and the same g is applied to the input and the target. C: for each window, k is drawn uniformly from {1, 2, 3}, then t uniformly from that speed's allowed starts ({1..14}, {1..8}, {1, 2}). Only the existing target frames enter the loss, and each video is weighted equally. D: the same data as C with a larger-reach architecture (Q2.12). The optional D+B model was not trained (see Section 5).

Q2.12 — Model D and its reach

How D was chosen. Three convolutional-recurrent designs with a strictly larger one-step reach and at most 721,176 parameters were fixed in advance (mm/models.py: D_CANDIDATES). The selection rule was fixed with them: the lowest mean validation E(2) over 1×, 2× and 3× at the final epoch (scripts/select_D.py). Both were committed before any candidate was trained. Each candidate was then trained with the full model-D protocol (speed augmentation, seed 0, 30 epochs). The winner's seed-0 run is model D seed 0, and seed 1 was trained afterwards with the same design. The test split was not used.

The 5×5-kernel design collapsed in epoch 2 to the trivial "almost-dark frame" solution (training loss stuck at 0.0402 for all 30 epochs, and the same validation error at every speed). The output sigmoid saturated and gradients vanished. Because the protocol forbids tuning the learning rate, the design was rejected rather than rescued. The 8×8-patch design has the flattest error across speeds but loses detail at 1× (its grid cells are 8 px wide). The dilated design wins on the pre-registered criterion.

Model D (chosen design "dil12"). Everything is identical to model A (pixel_unshuffle(4), two ConvLSTM layers with 64 hidden channels and Eqs. 3–4, a 1×1 head, pixel_shuffle, sigmoid, the 9-step rollout without teacher forcing, and the same training protocol), except that the 3×3 gate convolution of layer 2 is dilated by 2 (dilation 2, zero padding 2, so the grid stays 16×16). Dilation spreads the same nine taps over a 5×5 window at offsets {−2, 0, +2} cells, so the parameter count is unchanged at 480,784 (= model A, well under the 721,176 limit). This keeps model D a clean single-factor change from model C: only the reach differs.

Reach (same calculation as Q2.3; one cell = 4 px; only the two 3×3 convolutions move information):

  • Layer 1, a 3×3 kernel with dilation 1, moves information at most 1 cell = 4 px.
  • Layer 2, a 3×3 kernel with dilation 2, moves information at most 2 cells = 8 px.
  • Path uτ (or h(1)τ−1) → conv1 → conv2 → x̂τ+1: 1 + 2 = 3 cells = 12 px. Path h(2)τ−1 → conv2: 2 cells = 8 px. Cell states enter element-wise.

So reach(D) = 12 px per step > reach(A) = 8 px along a row or column (17 px against 11.3 px along the diagonal). The offsets that the two layers combine, {−1, 0, 1} + {−2, 0, 2} = {−3, …, 3} cells, are contiguous. Every displacement up to 12 px can therefore be carried in one step, with none of the gaps that stacking two dilated layers would leave. That covers the median 3× displacement of about 10 px (Q2.1). The 8×8-patch candidate would have reached 16 px, but it lost on the validation criterion.

If C had stayed bad at 3× while D did well, that would have isolated an architectural limit. C and D see identical data, so data cannot explain a difference between them, and the only remaining difference would be how far information can travel in one step. Our runs show something different: C already fixes 3× almost as well as D. The reason is the point made in Q2.9. Relating a digit's remembered position to its new position needs the two pieces of information to meet, and in model A they can meet across about 12 px (2 cells from the input plus 1 cell from the layer-2 state). That already covers the ≈ 10 px displacements at 3×. So 3× was unfamiliar, not out of reach. A gap remains in both models: E(2) at 3× is 43% (C) and 34% (D) above their own 1× value. D's ratio is slightly better, which is consistent with reach mattering a little at the 95th-percentile 3× displacements (≈ 13 px). Part of the gap is also intrinsic: one 3× step spans three real frames, with more bounces and more uncertainty, and Copy-last also worsens from 0.0548 to 0.0703.

Why more data cannot carry information further than the architecture allows. The reach is a property of the computation graph, not of the weights. The prediction at a pixel is a function only of the input and state values inside its one-step neighbourhood. For anything outside it there is no path, so the derivative of the output with respect to those inputs is exactly zero for every weight setting. Training data can only change weights. It can teach the network to use the connections it has, as C does, but it cannot create connections that do not exist. No amount of data lets a 3×3 stack see 20 px away in one step. Only a change to the architecture (larger or dilated kernels, bigger patches, downsampling) can do that.

Q2.14 — Did the fixes cost accuracy on the original 1× clips?

B: essentially no. E(5) at 1× is 0.0230 against 0.0223 for A (+3%), which is inside the seed spread (A: 0.0220–0.0226; B: 0.0223–0.0237). In return it buys consistency and an equal error on mirrored and rotated clips. That is clearly worth it. C and D: yes. E(5) at 1× rises to 0.0267 (+20%) and 0.0274 (+23%), and E(2) at 1× from 0.0189 to 0.0233 and 0.0245. With the epoch budget fixed, only about one window in three is now a 1× window, and the same network must cover a three-times-wider range of motions, so predictions get blurrier at 1×. Averaged over the three speeds, however, E(2) drops from 0.0382 (A) to 0.0284 (C) and 0.0288 (D), about 25% lower, and the catastrophic failures at 2× and 3× are gone. It is worth it whenever speeds other than 1× can occur, which is the point of a model that has "learned motion". If the deployment only ever sees 1× clips, the speed augmentation is a pure loss. D's extra reach did not pay for itself in our runs: it is slightly worse than C at 1×, equal at 3×, and about 9% slower per epoch.
